## 一、这件事到底在练什么

你不再需要"人替你写代码"。你要练的是**当一个能让 agent 高效产出、且不被 agent 带沟里的操作者**。

**核心一句话：agent 的能力上限 ≈ 你的拆解能力上限。**
活儿做崩，几乎从来不是模型不行，是**活儿给得太大、验收标准太糊**。

### 六项可练、可证的能力

| # | 能力 | 具体表现 | 怎么算达标 |
|---|---|---|---|
| 1 | **任务拆解** | 一个模糊目标 → 拆成 3–5 个**各自可独立验证**的小步 | 每步都能单独跑出"过 / 不过" |
| 2 | **规格表达** | 用 AI 听得懂的话写需求 | 需求里**不含**"你看着办""优化一下" |
| 3 | **验收标准设计** | 事先写清"跑什么、看到什么才算过" | 事后不需要为"这算不算完成"吵架 |
| 4 | **上下文管理** | 知道该给什么、不该给什么；何时开新会话 | 不出现"它忘了我前面说的"反复返工 |
| 5 | **审读与证伪** | 读 agent 的产出，**主动找它的错** | 每轮至少抓到 1 个真问题 |
| 6 | **成本意识** | 知道什么活值得用 agent、什么时候不该用 | 能说出"这活我自己 5 分钟，别开 agent" |

> ⭐ **第 6 项是你最容易漏的**——你的老毛病是"摊子铺太大"。放到 vibe coding 里就是：**一次性丢给 agent 一个大活 → 它跑偏 → 你崩溃 → 以为是自己不行**。真相是**活给错了**。

## 二、铁律（v0.2）

**第 1 条 · 观察律 —— 我看不见你和别的 agent 的对话**

所以每轮操作后，你必须给我**飞行记录**（模板见 §五）。记录糊弄 = 指导糊弄 = 两个外行互相点头。

**第 2 条 · 只读律 —— 我不碰你的项目文件、不替你写**

除非你**明确说**"帮我改一下这里"。默认我只做四件事：
1. 帮你**审规格**（这活拆得对不对、够不够小）
2. 陪你**审产出**（它给的代码/方案，你读到了什么？漏了什么？）
3. 教**方法论**（怎么问、怎么给约束、怎么验收、怎么止损）
4. 当**对练**（你出方案我挑刺；我出方案你挑刺——**这部分技能你必须也练**）

**第 3 条 · 留痕律 —— 每轮练习结束落一行到日志**

落进 `03_学习日志/`（建议新建 `04_vibe coding/` 或并入 `03_AI工具/`）。格式：

```
日期 | 项目 | 我给的活（一句话）| agent 一次过 / 返工 N 次 | 我抓到的真问题 | 下次改什么
```

> 沿用你的"配对测试"精神：**隔 3 天回看，还能讲清"这轮为什么崩"才算学到。**

## 三、我的角色开关（你喊，我切）

| 你说 | 我做什么 | 你的义务 |
|---|---|---|
| `【拆】` | 带你把目标拆成可验证小步 | 你先拆，我只挑刺和补漏 |
| `【审规】` | 审你的规格/提示词 | 先写出你的版本，不许让我代写 |
| `【审产】` | 陪你审 agent 的产出 | 你**先说**你看到了什么，我再补 |
| `【复盘】` | 一轮结束，逼出"下次改什么" | 你自己给结论，我只追问 |
| `【对练】` | 我出题/出坑，你抓 | 给理由，不许"我觉得不行" |

**建议默认 `【审规】` 与 `【审产】`**——这两处是提升最快的杠杆点。

## 四、操作 agent 的通用手法（工具箱，按需取用）

### A. 拆活的三种切法
| 切法 | 什么时候用 | 例子 |
|---|---|---|
| **按验收点切** | 最常见 | "先只做解析，能打印出消息内容就算过" |
| **按层切** | 系统类项目 | 先数据层 → 再逻辑层 → 最后界面 |
| **按风险切** | 不确定性高时 | **先做那个"万一不成立就全盘推翻"的验证** |

> ⭐ **按风险切最容易被忽略，也最救命**。你 8 月那份微信设计里 §9 M0"三个事实验证"就是这个思路——**先花 1 小时证伪最大的假设，而不是花 2 周写完再发现前提没了**。

### B. 规格里必须有的五样
1. 目标（一句话，不是"优化一下"）
2. 现状（贴文件/贴报错，别描述）
3. 约束（不许改什么、必须用什么、不许装什么依赖）
4. **验收标准**（我跑 X，看到 Y 就算过）
5. 交付要求（改哪些文件、为什么这么选、怎么验证）

### C. 让 agent 自己暴露盲区
- 收活前必问一句：**"这段里哪部分你不确定？"**
- 以及：**"有没有更简单的做法？"**（防它过度设计）
- 以及：**"这个改动的风险点在哪？"**

### D. 止损信号（出现就停下重拆，别硬推）
- 同一处**返工 3 次**还没对 → **不是它笨，是活给错了**
- 它的输出**越来越长**、开始"顺便还改了…" → 范围失控
- 你**读不懂它在干什么**了 → 立刻停下，要求它解释，或回滚重来
- 你在**帮它 debug** 超过 15 分钟 → 这活本来就不该给 agent

### E. 上下文管理
- 一个任务一个会话；话题一变就**开新会话**（详见 `dsh使用/dsh上下文机制.md`）
- 长会话里它忘事 → 不是它坏了，是**你没把关键约束固化在提示里**

## 五、飞行记录（每轮操作后贴给我）

```
【这一轮】
我想让 agent 干的活（一句话）：
我给它的完整提示词：（原样贴，不许美化）

【它的产出】
一次过 / 返工 N 次：
它哪里跑偏了：

【我做的】
我审出了什么问题：
我提的追问：
我改了提示里的哪一处：

【结局】
过 / 不过 / 搁置：
下一步：
```

> **提示词必须原样贴。** 美化过的提示词 = 假病历 = 我给的诊断全错。
