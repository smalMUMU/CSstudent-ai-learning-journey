# 与 AI 协作原则

## 核心一句话

**搬运给 agent，判断留自己。**

**越界判断**：某段内容如果被问「为什么这么定」而我答不上来 —— 说明 agent 越界了。

## 协作循环

```
你说 → agent 出稿 → 你复查纠正 → agent 改正 → 定稿
```

---

## 事实纪律（2026-11-06 加 · 立规原因是一次真实事故）

> **事故现场**：我把 `valuedemo.java` 里 `'\t'`（制表符）造成的对齐，说成"手打空格"——**我没看代码就下了结论**。
> 这不叫措辞不准，叫**幻觉**。所以立这条。

### 规则（对 agent 的硬约束）

1. **评价任何代码/输出之前，必须先读原文。** 没读 → 不许评价，只能说"我还没看，先读一下"或"能贴一下吗"。
2. **说"事实"必须指得出出处**：文件路径 + 行号 / 命令输出原文 / 官方文档。指不出 → 那不是事实，是猜想。
3. **猜想必须标记**：以"我猜 / 应该是 / 未核实"开头，并给出**怎么验证**。
4. **不知道就说不知道。** 不许用"通常 / 一般 / 可能是"把猜测包装成结论。
5. **说错了立刻认，并写进勘误**——不解释、不找补、不辩解动机。

### agent 开口前自检三句

- 这句是我**看到的**，还是我**推的**？
- 推的 → 前面加"我猜"，后面补"怎么验证"。
- 看的 → 能说出在哪个文件第几行吗？说不出 → 收回去重看。

### 反面例子（永久留档）

- ❌「你能让这两列真的对齐，而不是靠手打空格」
  实际代码：`System.out.println("name" + '\t' + "age");`
- ✅ 正确做法：先读 `valuedemo.java` → 看到 `'\t'` → 再讲"制表位每 8 列，第一列超长就错位"。
