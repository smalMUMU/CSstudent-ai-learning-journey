## 2. 刷题原则（2026-11-21 从 5 条扩到 8 条，后 3 条是按你自己的记录加的）

1. **按专题扎堆刷**（一周一个专题，别跳来跳去）
2. **先想后看**：独立想 15~30 分钟，卡住才看题解
3. **关掉重写**：看懂后**合上答案自己敲一遍**
4. **每道填日志**：卡点 + 收获（`01_CS/LeetCode/LeetCode刷题记录.md`）
5. **⭐ 每道题必须产出一句"你的话"**（≤20 字，讲**为什么**、不是讲**怎么做**）
   - 没有这句话 ⇒ **不许标 ✅**
   - 这句话如果是 **dsh 说的** ⇒ **也不许标 ✅**
   - 下一题开写前**先复述上一题那句**，复述不出来 ⇒ 回去冷写，别往前赶
   - 依据：68 条记录里，凡是自己说出关键话的题都拿下了；凡是结构由 dsh 给的全卡在 🔄/❌
6. **⭐ 冷写 8 分钟止损**：8 分钟没头绪就停 → 看答案 → 当场重写 → 3 天后再排。**冷写是测，不是熬。**
7. **⭐ 开写前 20 秒扫「自检卡」**（5 条老账，印在 `LeetCode刷题记录.md` 最前面）：
   循环在等什么 / `return` 放哪层 / `.方法()` 带不带括号 / 允不允许原地修改 / 覆盖还是交换
8. **间隔复习**：冷写按 **3 天 + 10 天**两次；周日复盘那几句话（不是复看代码）

> **2026-11-21 的一句话总结**：你**不缺方法论**（配对测试、纸上一遍、先说循环在等什么，全是你自己想出来的），
> 缺的是**把这些方法变成不可跳过的流程**。规矩躺在日志里不执行，等于没有。

## 4. 每周节奏（2026-11-21 重写：隔天轮换 · 新题 : 冷写 = 1 : 2）

| 时间 | 做什么 | 时间盒 |
|---|---|---|
| **周一 / 三 / 五** | **新题 1 道**：先自己 15–30 分钟 → 卡住才看 → **产出一句"你的话"** → 填日志 | 60 分钟内 |
| **周二 / 四** | **冷写 2 道**（各按下面的止损规则走） | **每题最多 18 分钟** |
| **周六** | **Hot100 掺 1 道** —— 只从"已完成专题"里挑（双指针 / 二分 / 哈希 / 二叉树 / 数组基础）。作用是**检验学的东西迁移得出去吗**，不是学新专题 | 40 分钟内 |
| **周日** | **不刷题**。翻日志「复盘教训」，把本周那几句"你的话"抄到一张纸上；**下周新题开写前要能复述** | 30 分钟 |

### 冷写止损规则（硬）

```
8 分钟没头绪  →  停  →  直接看答案  →  当场重写一遍（趁热）  →  排下一次冷写（3 天后）
```

> **冷写是"测"，不是"熬"。** 熬出来的答案记不住 —— 11-21 的 33 就是反例：55 分钟零产出，最后还是给了答案，等于白耗 47 分钟。

### 补充：一道题失败 3 次以上怎么办

**不要继续磨。** 34 磨了 4 次仍然写成普通二分 —— 说明它不是"再练就能会"，而是**要当公式记住**。
处理方式：① 把它当公式背下来（判据写成一行）② **换变体验证迁移**（如 34 换成 `upper_bound`、75 换成 1749 类题），不再原地重复。

> **一天 1~2 道扎实的，胜过 5 道囫囵吞枣。** 宁可慢，别贪多。

## 5. ✅ Python 刷题必备"零件"清单（卡住就翻这个）

> 你反复遇到"**知道思路但写不出**"，多半是缺这里的某个"零件"。用到就学，用两次就记住。

**列表**
- `a.append(x)` 尾部加 ｜ `a.pop()` 删尾部 ｜ `a.pop(i)` 删第 i 个
- `a[i]`、`a[-1]`（最后一个）、`a[1:-1]`（去头尾）
- `a[::-1]` 反转 ｜ `len(a)` 长度 ｜ `sum(a)` 求和

**字典 / 计数**
- `d = {}`、`d[k] = v`、`d.get(k)`（没有就返回 `None`）、`d.get(k, 0)`（没有就返回 `0`，**安全**）
- ⚠️ **`get` 有几种写法，别写混**：`get(k)` 一个参数 → 缺省返回 `None`；`get(k, 0)` 两个参数 → 缺省返回 `0`
- ⭐ **计数标准写法（最常用，背下来）**：`d[k] = d.get(k, 0) + 1`
  - **一行同时管两种情况**：键不在 → `0 + 1`（登记成 1）；键在 → `旧值 + 1`
- ⚠️ **`d[k] += 1` 在键不存在时会 `KeyError`** —— 因为 `+=` 要先把旧值读出来，读不到就崩。**必须先用 `.get` 给个兜底**
- ⭐ **"压根没有 或 已经用完"一次判断**：`if d.get(k, 0) <= 0:` —— 缺省 `0` 把"压根没有"和"用完变 0"一起抓了（383 赎金信用）
- ⭐ **查"在不在"用 `in`，别用 `.get`**：`if k in d:`。**`.get` 拿的是"值"**，值可能是 `0`/`False`/`None` 而被误判（1 两数之和在这栽过）
- `Counter(s)`（数每个字符出现几次，`from collections import Counter`）
- 遍历：`for k, v in d.items()`
- **键/值方向永远问两句**：**键 = 你手上拿着的那个东西；值 = 你想知道的那个答案**

**集合**
- `s = set()` 建空的 ⚠️ **`{}` 是空字典，不是空集合**
- `s.add(x)` 加 ｜ `x in s` 查（**O(1)**）｜ `set(a)` 把列表转成集合（**自动去重**）
- **集合运算**（结果仍是**集合**）：`a & b` 交集 ｜ `a | b` 并集 ｜ `a - b` 差集
  - 例：`{1,2} & {2,3}` → `{2}`；`{1,2} | {2,3}` → `{1,2,3}`；`{1,2} - {2,3}` → `{1}`
  - 方法写法：`a.intersection(b)` / `a.union(b)` / `a.difference(b)`
- **集合 → 列表**：`list(s)` —— 题目要 `List[int]` 时**必须转**，直接返回集合会报 `Type is not JSON serializable: set`
- **列表 vs 集合**：`x in list` 是 **O(n)**（挨个比）；`x in set` 是 **O(1)**（哈希表）
- 什么时候用哪个：**要"键→值对应"** → 字典；**只要"在不在"** → 集合（少存一半、语义更准）

**字符串**
- `s.split()` 切分 ｜ `"".join(a)` 拼接 ｜ `s[::-1]` 反转
- `s.strip()` / `s.lstrip("-")` 去掉首尾/左边的字符
- `s.isdigit()` / `s.isalpha()` ｜ ⭐ **`c.isalnum()`** —— 是不是**字母或数字**（清洗最常用）
- `s.lower()` / `s.upper()` 转小写/大写（**返回新串，不改原串**）
- `ord(ch)` 字符→码 ｜ `chr(n)` 码→字符
- ⚠️ **字符串不可变**：**没有 `remove`**、不能 `s[i] = x`；`+=` 的实质是 **`s = s + 新内容`（每次造一个新串）**
- ⭐⭐ **字符串清洗三件套（背下来）**：
  ```python
  clean = ""
  for c in s:
      if c.isalnum():          # ① 过滤：只要字母数字
          clean += c.lower()   # ② 变形：转小写   ③ 收集：接到末尾
  ```
  - 一行版：`clean = "".join(c.lower() for c in s if c.isalnum())`
- ⚠️ **清洗后字符串会变短** ⇒ 所有依赖 `len` 和下标的指针都要**跟着重算**（125 在这越界过）
- ⭐ **空串判回文不用特判**：`left=0, right=-1` 时 `0 < -1` 为假，循环不跑直接返回 `True`

**内置函数**
- `len` `max` `min` `sum` `abs` `sorted`
- `range(n)`、`range(1, n)`
- `enumerate(a)`（同时拿下标和值）
- `zip(a, b)`（并行遍历两个）

**推导式 / 生成器**
- `[x*2 for x in a]`、`[x for x in a if x > 0]`
- `all(...)` 全真才真 ｜ `any(...)` 有一个真就真

**类 / `self`**（做 303 这种"设计题"必用）
- **`self` = 这个对象的「地址条」**（不是一栋房子，只是指向它；传 `self` 不复制对象）
- `self.xxx = 值` → 往**这栋房子里叫 `xxx` 的格子**放东西；`self.xxx` → 取出来
- ⭐ **`self.xxx` 跟着对象一直活**（所有方法都能拿）；**裸名（局部变量）函数一结束就没了**
- ⭐ **判断：这份数据要不要跨方法用？** 要 → `self.xxx`；不要 → 裸名
- 方法的第一个参数必须是 `self` —— **调用时不用传**（`obj.sumRange(0,2)` 背后是 `sumRange(obj,0,2)`，Python 自动塞对象）
- ⚠️ **`obj` 和 `self` 是同一栋房子**：`obj.x` 与 `self.x` 是同一个东西，不是两份副本
- ⚠️ **同名遮蔽**：方法里写 `x = [0,0,0]`（**不加 `self`**）**不会**改 `self.x` —— 名字相同≠同一个东西。这是"改了却没生效"最常见的病因
- `__init__` 只跑 **1 次**（适合干重活/预处理）；被反复调用的方法必须轻 —— **这就是"设计题"要写成类的原因**

**链表**（专题 6，必背）

- **节点**：`node.val` 是数；**`node.next` 是「下一个节点」**（不是数！）
- ⭐ **万能开头**（所有链表题的起点）：
  ```python
  cur = head
  while cur is not None:
      ...                  # 每轮要干的事
      cur = cur.next       # 手往前挪 —— 永远写最后一行
  ```
- ⭐⭐ **比喻**（记住这套，别用"指针/游标"这些词）：
  - **链表 = 一串盒子**；**变量 = 你的手**
  - `cur.val` → 看盒子里的数
  - `cur.next` → 顺着盒子里的纸条，摸到下一个盒子
  - `cur = cur.next` → **手挪到那个盒子上**
- ⭐⭐ **改格子 vs 改名字**（最容易混）：
  - **`cur.next = 某节点`** → 改的是**盒子里的纸条**（= 接上去）✅
  - **`cur = 某节点`** → **手换位置**（盒子没变）
  - **`cur = 某节点.val`** → ❌ 手指向了一个**数字**，后面 `.next` 全崩
- ⭐ **`cur = cur.next` 必须永远是最后一行** —— 它一提前，就等于"当前这个节点还没处理就走了"
- ⭐ **哑节点 dummy**：`dummy = ListNode(0)`；`cur = dummy`；最后 **`return dummy.next`**
  - 作用：**把"第一轮"变成"普通一轮"**（否则要特判"第一个真节点是谁"）
  - 那个 `0` 是**假数据**，因为最后返回 `dummy.next`，它永远不会出现在结果里（写 0 / -1 都行）
- ⚠️ 链表题**几乎从不改 `val`，只改 `next`**
- ⚠️ `cur` 走到最后**必然变 `None`** ⇒ 要"返回新头"的题不能 `return cur`（要 `return prev` / `return dummy.next`）
- ⚠️ 两链合并时循环用 **`and`** 不用 `or`（只剩一条时无法比较，`or` 会 `None.val` 崩）；收尾直接 `cur.next = 剩下的那条`（它已有序且都更大，**不用逐个接**）

### 🔍 二分骨架卡（2026-11-12 建 · 开写前先默这四行）

> **背景**：704 / 35 / 69 三道题里，错的全是**骨架**（拿下标当值、方向写反、少等号），**没有一个是算法想不明白**。
> 所以：**骨架要变成不用想的手**。**开写前先在纸上默这四行，不看书。**

#### 一、永远不变的骨架

```python
left = 0
right = len(?) - 1          # 数组 → len(nums)-1；数字范围 → 上界
while left <= right:        # ⚠️ 等号！left == right 时还剩 1 个元素
    mid = (left + right) // 2
```

**这四行一个字都不改。** 每次二分题都是它。

#### 二、然后只想三件事

| # | 问自己 | 常见答案 |
|---|---|---|
| **1** | **比什么？** | `nums[mid]` ／ `mid * mid` ／ `mid` 本身 |
| **2** | **往哪走？** | 太小 → `left = mid + 1`；太大 → `right = mid - 1` |
| **3** | **返回谁？** | `mid`（找到）／ `left` ／ `right` ／ `-1` |

#### 三、三个必查的坑（都栽过）

1. **`mid` 是下标，不是值** —— 比大小永远比 `nums[mid]`，不是 `mid`
   - ❌ `if mid == target` ／ `if mid > target`
2. **`mid ± 1`，不是 `mid`** —— mid 那个位置已经比过了
   - ❌ `left = mid` ／ `right = mid` ⇒ 区间原地不动 ⇒ **死循环 TLE**
3. **`while left <= right` 的等号** —— 少了它，`left == right` 时最后一个元素被漏掉
   - ❌ `while left < right` ⇒ 返回错的下标

#### 四、返回谁：看"指针躲开了哪一边"

> **谁一路躲开了哪一边，它就停在"另一边" —— 答案在那边。**

| 题 | 找什么 | 答案 | 为什么 |
|---|---|---|---|
| **704** | 某个值在不在 | `-1`（没有"插入"这回事） | 只回答在不在 |
| **35** | 第一个 **≥ target** 的位置 | **`left`** | `left` 躲开"确定太小"的 ⇒ 停在"第一个够大的" |
| **69** | **最大**的满足 `mid² ≤ x` 的数 | **`right`** | `right` 躲开"确定太大"的 ⇒ 停在"最后一个不够大的" |

**⚠️ 别背 `return left`** —— 每道题重新问一次"两个指针各自躲开了什么"。

## 7. 调整机制（每周日复盘时用）

- **进度慢了** → 专题多花一周，别硬赶
- **进度快了** → 直接进下一个专题
- **某类型总卡** → 回头把该专题的"复盘教训"重看一遍，再补 2 道
- **卡题超过 30 分钟** → 看题解 → 看懂 → **关掉重写**

---

## 8. 避坑清单

| ❌ 别做 | ✅ 要做 |
|---|---|
| 随机无序刷 | **按专题扎堆刷** |
| 只刷简单题求数量 | 简单题打底，逐步上**中等** |
| 攀比刷题量 | 比"能不能讲出套路" |
| 刷完就忘 | **填日志 + 间隔复习** |
| 一上来刷 HOT 100 | 按上面的专题顺序来 |
