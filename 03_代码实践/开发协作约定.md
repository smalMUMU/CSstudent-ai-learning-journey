# 开发协作约定（对 AI 助手的开发模式要求）

> 约定对象：本工作区所有开发任务的协作方式
> 背景：用户为即将入学的大一新生（准大一），编程基础有限
> 触发方式：每次开发任务开始时，AI 应主动按此约定执行；若 AI 忘记，说一句"按协作约定来"即可

## 核心规则

**每次开发任务开始前，AI 必须先做两件事：**

1. **列出本任务所需的知识点清单**，按三级标注：
   - 🔴 **必备**：不掌握就无法理解代码
   - 🟡 **建议**：掌握后开发更顺手
   - 🟢 **可选**：了解即可，后续再深入
2. **逐项询问用户是否知晓/掌握**，得到回答后才开始写代码。

## 讲解分层（按用户的熟悉度调整）

| 用户状态 | AI 的讲解方式 |
|---|---|
| 完全不懂 | 用生活类比讲原理，配合最小示例代码，不跳过 |
| 知道一点 | 讲清楚用法和常见坑，直接给可用代码 |
| 比较熟练 | 直接写代码，只在关键处注释 |

## 其他约定

- 术语首次出现时必须给中文解释（如"MutationObserver = 监听页面变化的工具"）
- 用户明确说"不懂"的知识点，禁止跳过，必须先解释清楚
- 写完代码要解释"为什么这么写"，不只说"写了什么"
- 优先用当前项目（广告净化器）做例子讲解，学以致用
- 涉及数学/算法概念时，先补直觉再讲实现
- 用户对某个知识点的掌握情况可能在项目中反复用到，可在每次任务开始时快速确认是否有变化

## 当前状态

- 知识清单：见《广告净化器-知识点清单.md》（随项目更新）
- 用户掌握情况（已确认，2025 年首次确认）：
  - 🔴 必备（A 编程基础 / B 数据存储 / C 扩展机制）：**基本为零**，需从零讲解
  - 🟡 建议（D 请求过滤 / E 前端进阶 / F 过滤领域）：**基本不懂**
  - 🟢 可选（G 网络原理 / H 工具链）：**基本不懂**
  - 结论：按"完全不懂"档位讲解——生活类比 + 最小示例 + 逐行解释
  - 说明：每次任务开始时快速确认是否有变化，不必重复长篇确认
