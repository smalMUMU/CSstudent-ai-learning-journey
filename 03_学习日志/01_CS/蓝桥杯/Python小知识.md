## ① `from datetime import datetime` 到底导入什么

```
from   datetime    import   datetime
      ↑模块（工具箱）        ↑类（里面的一件工具）
```

- Python 标准库里有个**模块**叫 `datetime` —— 相当于**一个工具箱/一个文件**
- 箱子里有好几件工具：`datetime`（造时间对象用）、`date`、`timedelta`…
- `from X import Y` = **从工具箱 X 里拿出 Y**，之后就能直接叫 `Y`
- **名字一样是历史遗留**（工具箱和里面的一件工具同名），所以看着别扭

**对照你自己写过的**（pi_ai）：
```python
from tools import TOOLS, run_tool     # 从 tools.py 里拿出两个名字
```
**完全同构。**

## ② `datetime.strptime(n, "%Y-%m-%d %H:%M:%S")` 为什么长这样

读法：**str**ing **p**arse **time** = "**文本 → 解析 → 时间**"

| 部分 | 是什么 |
|---|---|
| `datetime` | 那个"模子"（类） |
| `.strptime` | 模子自带的功能：把文字解析成时间 |
| 第 1 个参数 | 要解析的**那段文字** |
| 第 2 个参数 | **说明书**：告诉它每一段是什么 |

**为什么必须有说明书**：同一串字可以有好几种读法。
`01/02/2022` 是 1 月 2 日还是 2 月 1 日？**不说明就是歧义。**

| `%Y` 四位年 | `%m` 月 | `%d` 日 | `%H` 时（24 小时制） | `%M` 分 | `%S` 秒 |
|---|---|---|---|---|---|

> **一句话**：给一段文字 + 一张格式说明书 → 还你一个**时间对象**（时间对象才能相减）。

## ③ 点号 `.` = "谁的能力" ⭐（最重要的一条）

`append`、`total_seconds`、`strptime` —— **是同一类东西**，都是"点号后面的能力"。

> **`谁.什么()` = "让这个东西做它能做的事"。**

| 写法 | 点**前面**是谁 | 意思 |
|---|---|---|
| `times.append(x)` | 一个**列表** | "列表自己会 append" |
| `(t2 - t1).total_seconds()` | 相减得到的**一段时长** | "时长自己会换算成秒" |
| `datetime.strptime(...)` | 一个**类**（模子） | "这个模子自带解析功能" |
| `msg.get("tool_calls")` | 一个**字典** | "字典自己会安全取值" |
| `"张三 12".split()` | 一个**字符串** | "字符串自己会切" |

**精度上的小差别（知道就行）**：
- `append` / `total_seconds` / `split` / `get` → **某个具体东西**的能力
- `strptime` → **整个类**的功能（不用先有对象）

**但写法都是 `谁.什么()`，用的时候不用区分。**

### 和方括号的分工（你在 pi_ai 里两种都写过）

| 写法 | 含义 |
|---|---|
| `resp["message"]["content"]` | **取**里面装的东西 |
| `msg.get("tool_calls")` | **用**它自带的能耐 |

## ④ 读报错：**类型名字就是线索**

报错原文：`TypeError: unsupported operand type(s) for -: 'str' and 'str'`

| 报错里的字样 | 意思 | 该去查哪 |
|---|---|---|
| `'str' and 'str'` | 你在对**字符串**做运算 | 往回找 `append` 那一行，看存进去的是什么 |
| `'datetime' and 'str'` | 一半转了一半没转 | 同上，有个地方漏了 `strptime` |
| `'timedelta' object has no attribute 'split'` | 你手里是**一段时长**，却当它是字符串 | 方法用错对象了 |
| `invalid literal for int() ...: ''` | `int()` 收到空字符串 | **没喂输入**，不是代码错 |
| `can't open file ... No such file` | | **目录错了**，不是代码错 |

> **顺着报错里的类型名，往回到"这东西是哪来的"——90% 一眼找到。**

## ⑥ 二级排序：**两次 `sort` 的顺序，和你想的相反** ⭐

> 2026-11-15 在 T02 上撞到的（**教练一开始也讲反了，靠实测才发现**）。

**需求**：金额从高到低；金额相同的，姓名从小到大。

**错误写法**（先主后次 → 结果变成按姓名排）：
```python
pairs.sort(key=lambda p: p[1], reverse=True)   # 金额降序
pairs.sort(key=lambda p: p[0])                 # 姓名升序 ← 它在最后，它说了算
```

**正确写法**（**次关键字先排，主关键字后排**）：
```python
pairs.sort(key=lambda p: p[0])                  # ① 先排"次关键字"：姓名升序
pairs.sort(key=lambda p: p[1], reverse=True)    # ② 后排"主关键字"：金额降序
```

### 为什么

`sort` 是**稳定排序**：它只重排"key 不同的"，**key 相同的保持原来的次序**。

所以 **最后一次 `sort` 的 key 才是主关键字**，前一次的次序被保留下来当"并列时的次序"。

### 实测（样例输入跑了两次，只有顺序不同）

| 顺序 | 输出 |
|---|---|
| 先金额后姓名（**错**） | 张三 12 / 李四 8 / 王五 12 / 赵六 30 / 钱七 8 ← 变成按姓名排 |
| 先姓名后金额（**对**） | 赵六 30 / 张三 12 / 王五 12 / 李四 8 / 钱七 8 ✅ |

> **口诀**：**主关键字放最后一次。** 想不清楚就**跑一遍样例**——嘴会骗人，输出不会。
