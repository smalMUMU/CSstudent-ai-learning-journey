### 一、数组双指针 / 原地修改
- **原地修改数组，优先用双指针**，别改列表长度。
- **"原地移除" ≠ 真删**！它是"把要留的元素搬到前面（覆盖掉不要的）+ 返回有效长度 `k`"——**数组物理长度不变**，题目只看前 `k` 个，后面是啥无所谓。真删（`remove`）每删一个要挪后面所有元素，O(m·n)，所以不用。共同题：26 / 27 / 80 / 283。
- 遍历若涉及 `i-1`，**循环起点必须是 1**，否则 `nums[-1]` 取到末尾元素。共同题：26 / 27 / 283 / 1480。
- ⭐ **同一个变量，定义成"计数"还是定义成"位置"，决定你怎么推下标——这就是 off-by-one 的根源**（2026-10-09 从 80 的 `length` 上挖出来的）：
  - **计数口径**：`length` = 已覆盖的**个数** → 占了下标 `0 .. length-1` → 最后一个是 `length-1`、**倒数第二个是 `length-2`**
  - **位置口径**：`length` = **下一个要写的位置** → 上一次写在 `length-1`、再上一次在 `length-2`
  - 两个口径在这题里**数值上恰好总是相等**，因为覆盖是"**从 0 开始、连续写、中间不留空位**"
  - ⚠️ 但一旦写入**不连续**（允许空位），"已覆盖个数"和"下一个要写的位置"就会**分家** ⇒ **笔记/代码里必须写清是哪个口径**，否则连自己回头看都会读错
- **同一族的比较对象会升级**：26 是"跟已保留串的**最后一个**（`k-1`）比"，80 是"跟已保留串的**倒数第二个**（`k-2`）比"——**不是跟原数组的邻居比，是跟"已保留的那一串"比**（26 里两者碰巧同位置所以看不出）。想通这层，**93（每个数最多 K 个）可直接推**。

### 五、★ 通用语法点（反复踩的，写题前扫一眼）

1. **方法调用要加 `()`**：`sort()`、`isdigit()`、`pop()`…… 写 `sort`（没括号）是"方法本身"，不是执行。（踩过 3 次）
2. **`[x] * n`（列表重复）≠ 数字 × n**：要"n 个 0"写 `[0] * n`；写 `len(nums) * 0` 得到的是**数字 0**。
3. **`append` 是"加一个元素"，赋值是"变成它"**：`a.append([0]*n)` → 会变**嵌套列表**；要 `a = [0]*n`。
4. **`else` 是兜底（一定执行）；`elif` 只是另一个条件（可能一个都不执行）**：该兜底时用 `elif` → 某情况什么都不做 → 常导致**死循环**。
5. **`while` 后面是"继续条件"**（不是"退出条件"）：为真就继续。（58 那题的顿悟）
6. **负索引陷阱**：`nums[-1]` 是"最后一个"，**越界不会报错、只会取错值**——所以"先判越界、再访问"。
7. **★ `and` / `or` 的"短路求值"**：`A and B` **从左往右算**，**A 为假就直接返回，不看 B**（`or` 则：A 为真就不看 B）。→ 所以"**先判越界、再访问**"时，**越界判断必须写在【左边】**：
   - ✅ `m > 0 and nums1[m-1] > nums2[n-1]` → `m == 0` 时**短路，右边根本不算**（安全）
   - ❌ `nums1[m-1] > nums2[n-1] and m > 0` → **危险访问（`nums1[-1]`）先发生了**，护栏在后面，**来晚了**（88）
   > 一句话：**`and` 不是"事后拦"，是"边走边拦"——顺序决定它拦不拦得住。**
8. **`m`/`n` 这类参数常是"个数"不是下标** → 最后一个下标是 `m-1`。
9. **写代码必须用英文标点**：全角 `，（）""` 会直接 `SyntaxError`。
10. **"状态在迭代间传递"**：循环里算出的变量（如 `carry`）留给**下一轮**用；程序是**自上而下**执行的。
11. **`else` 不能带条件**：带条件的只能是 `if` / `elif`；`else` 是"其他所有情况"。
12. **`return` 的位置要专门检查一遍**（已犯 4 次）：挡住循环前（死代码）／藏在 `if` 里（漏返回 `None`）／陷在循环里（只跑一轮）／**藏在 `for` 的 `else` 里（后面的元素永远查不到 —— 1275 犯过 3 次）**。自查句：**"这一轮还没跑完就返回，对吗？"**
13. **`for` 后面跟的必须是"一串现成的东西"**；`for` 每轮只做一件事：**从右边取下一项、塞给左边**。左边几个名字就把该项拆几份（`for i, (r, c) in enumerate(moves)` 是**两层**拆包）。

### 七、二叉树与递归（2026-11-04 归纳 · 含他找来的图解要点）

**树 vs 链表**：链表每个节点**一条线**（`next`）；树每个节点**最多两条线**（`left` / `right`）⇒ **树会分叉 ⇒ 一条 `while` 走不了 ⇒ 必须递归**。

**递归三要素（写任何递归题先摆这三样）**

1. **出口**：`if node is None: return`（"递归的安全网"）
2. **做当前**：这一层要干的事（`res.append(node.val)` / `swap` / 算数）
3. **交给下面**：`dfs(node.left)` 和 `dfs(node.right)`

**"派人"模型（理解递归调用自己）**
`dfs(1)` 记 1 → 派 `dfs(2)` 走左边 → 派 `dfs(3)` 走右边。**派下去之后原地等**，等对方整棵做完才继续下一行（像打电话："A 说先问一下 B"）。
**每次调用都是一个新副本，各有各的 `node`，互不影响**；`res` 则始终是同一个列表。

**⭐⭐ `append` 的位置 = 遍历顺序（一道题换三道）**

| 遍历 | 顺序 | `res.append(node.val)` 放哪 |
|---|---|---|
| **144 前序** | 根 → 左 → 右 | `dfs(left)` **之前** |
| **94 中序** | 左 → 根 → 右 | 两个 `dfs` **之间** |
| **145 后序** | 左 → 右 → 根 | 两个 `dfs` **之后** |

同一棵树（`1 / (2,3) / (4,5)`）的结果：
**前序 `1 2 4 5 3` ／ 中序 `4 2 5 1 3` ／ 后序 `4 5 2 3 1`**
**辨别口诀：前序开头是根、后序结尾是根、中序开头是最左。**

**⭐ 后序的"关门打卡"（他找的图里说得最准）**

> "每次调用 `dfs` 就像在**纸上写下未完成的任务**，最底层的 `None` 触发 `return` 后，程序沿路径**回溯**。由于是后序，父节点必须等**左右子树全部打卡完毕**后，才能最后'关门打卡'（`res.append`）—— 这也是为什么 `1` 是**最后**一个被记录的。"

后序执行轨迹：`1 → 2 → 4` → 回 2 → `5` → 回 2 → 回 1 → `3`
`res`：`[] → [4] → [4,5] → [4,5,2] → [4,5,2,3] → [4,5,2,3,1]`

**闭包（为什么 `dfs` 里不用传 `res`）**
`dfs` 定义在外层函数**里面** ⇒ 能直接看见外层的 `res`；**不在类里 ⇒ 不用 `self`**。
（对比 232 的 `_fill`：它是**类的方法**，所以必须 `self._fill()`）

**两种递归形状（专题 8 的分水岭）**

| 形状 | 例子 | `dfs` 返回什么 |
|---|---|---|
| **往下塞** | 144 / 94 / 145 | 什么都不返回，只 `append` |
| **往上汇总** | 104 最大深度 / 226 翻转 / 101 对称 | **返回一个值**，父节点要用子节点的返回值 |



**「往上汇总」的执行轨迹（104 那棵树）**
数字是**从叶子往上冒**的：`4 → 1`、`5 → 1`、`2 → 2`、`3 → 1`、`1 → 3`。
**节点 2 算出 `2` 的那一刻，节点 3 一步都还没走** —— 左子树整片走完才轮到右子树，这就是"深度优先"的字面意思。
**空的那层必须交回数字 `0`**：不是"没结果"，是"这棵空树深度为 0"，因为上一层正张着手等这个数去比大小。

**「往上汇总」的两个致命动作（11-06 冷写 104 时全踩了）**

1. **`left = dfs(node.left)` 不是"拿一个现成的值"** —— 那个值是**下一层 `return` 出来的**。下一层不 `return`，这里接到的就是 `None`。他原话："不是直接把函数值赋值给 `left`，而是把函数**递归后的值**交付给 `left`"。
