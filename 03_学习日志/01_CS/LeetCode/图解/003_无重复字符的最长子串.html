为什么原解法可以继续优化？（点击展开 / 收起核心思路）
1. 原解法的瓶颈：线性查找 + 头部出队
s[i] in path 需要遍历列表，path.pop(0) 会把后续元素整体前移，两者都是 O(K) 操作。
2. 第一步优化：Set + 左指针
用 seen = set() 实现 O(1) 判重，用 left 指针代替 pop(0)，总时间降到 O(N)。
3. 第二步优化：HashMap 一次跳跃
记录每个字符上次出现的下标 last_seen[c]，遇到重复时直接把 left 跳到 max(left, last_seen[c] + 1)，省去内层 while。
4. 常数级极致：ASCII 128 定长数组
如果字符集为 ASCII，用 [-1] * 128 替代字典，避免哈希计算，空间 O(1) 且运行最快。

4 种解法复杂度与适用场景对比
解法 时间复杂度 空间复杂度 核心优势 / 注意事项
原解法：List + pop(0) O(N²) O(min(N, M)) 直观易写，但 in 查找与 pop(0) 均耗时。
优化 1：Set + 双指针 O(N) O(min(N, M)) 左右指针各最多走 N 步，面试最推荐的清晰写法。
优化 2：HashMap 跳跃 O(N) O(min(N, M)) 直接跳过重复字符；必须用 max(left, last[c]+1) 防止 left 回退。
优化 3：ASCII 128 数组 O(N) O(1) 定长数组代替哈希表，仅限 ASCII 字符（若含 Unicode 请用优化 2）。
