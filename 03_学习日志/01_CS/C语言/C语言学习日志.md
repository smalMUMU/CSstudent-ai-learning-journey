## 🧱 为什么"C 不如 Python 熟"（2026-10-25 自查）

> 我自己的判断："我的 C 语言熟悉程度不如 Python。" —— **这个判断是对的，但原因不是能力。**

**同一个逻辑，C 要你亲手多做 10 件事**（Python 全部自动或一句带过）：

| 事情 | **Python** | **C** |
|---|---|---|
| 声明类型 | 不用写 | `int n;` / `double s;` |
| 语句结尾 | 换行即可 | **`;` 一个不能少** |
| 代码分块 | 缩进 | **`{}`**（缩进对 C 只是"给人看"） |
| 打印 | `print(x)` | `printf("%d", x)` + **自己配占位符** |
| 读入 | `int(input())` | `scanf("%d", &n)` + **取地址 `&`** |
| 逻辑运算 | `and` / `or` / `not` | `&&` / `\|\|` / `!` |
| 字符 vs 字符串 | 都是 `str` | `'a'` 是 char（编码），`"a"` 是字符串 |
| 序列 | `list` 自带长度、能扩容 | **定长数组**、没有 `len`、会越界 |
| 除法 | `/` 真除法、`//` 整除 | `/` **自带整除**（反复栽） |
| 求幂 | `3**i` 精确 | `pow()` 返回 **double**（今天栽） |

**时间差也摆在这**：Python 从暑假 8 月写到今天（16 道题 + agent + 高数练习代码）；C 才第 2 周。

### ⚠️ 更要紧的一条：**Python 里"熟悉的路"在 C 里往往是"更贵的那条"**

> 2026-10-28 我自己的话：**"我想到过边读边比较，但我还是选择了比较熟悉的路径。"**
> 诊断：思想上看到两条路，但只有一条"走得动"（Python 的写法我熟）→ 被迫走落后的那条。**这是语法库存问题，不是判断力问题。**

| Python 里熟悉又免费的 | **C 里该换成的** | 原因 |
|---|---|---|
| `min(list)` / `max(list)` | **边读边比**，一个变量 | 不用存，还避开初值陷阱 |
| `sum(list)` | 累加器 `s += x` | 同上 |
| `len(list)` | 自己用 `n` 记着 | **C 数组不知道自己是多长** |
| 先 `list` 存下来再遍历 | 边读边算，或存数组 | 存了就要多走一遍 |
| `list(range(n))` | `for` 计数 + 每轮 `scanf` | C 没有"现成的序列" |
| 切片 `s[::-1]` | 手工反转 | C 没有切片 |

> **结论**：Python 里很多能力是"免费"的（自带长度、自动扩容、`min` 自带初值），C 里全要自己付钱。**"先存下来再处理"在 Python 里便宜，在 C 里最贵。**

### 变熟只有一条路

1. **每道题手敲，不复制**（打字量就是熟练度）。
2. **每个错都落盘**（这个文件就是干这个的），下次开写前扫一遍清单。
3. **不追求快**：现在写 10 题的时间，以后够写 3 题——因为上面那 10 处手工活会变成肌肉记忆。

> 判据：**能不看资料默写出来**才算熟（这就是冷写日程的由来）。"看得懂"和"熟"之间差的就是手敲的次数。

## 🛡️ 防御性编程（C 版 · 2026-10-25 建）

> 触发点：练习3-5 忘了处理"输入不是 21 世纪"的情况。我自己的话：**"我知道要防御性编程，但不知道 C 里怎么设。Python 加个 return 就立刻结束，太简单了。"**

### 一、本质差别：Python 有异常，C 没有

| | **Python** | **C** |
|---|---|---|
| 出错怎么中断 | `raise` / 异常往上抛，一层层跳出去 | **没有异常**。只有 `return`（一层一层退）或 `exit()`（直接杀进程） |
| 怎么告诉调用者"失败了" | 抛异常 / 返回 `None` | **看返回值**（约定：0 = 成功，非 0 = 失败；或返回 -1 / NULL） |
| 所以防御性编程靠什么 | `if 不合法: return / raise` | **`if 不合法 { 处理; return; }` + 检查每个函数的返回值** |

> 一句话：**C 没有"自动报警"，你必须自己设岗哨。**

### 二、C 里能"提前结束"的四个工具

| 目的 | Python | **C** |
|---|---|---|
| 函数提前返回 | `return x` | **`return x;`** |
| **退出整个程序** | `sys.exit()` | **在 `main` 里 `return 0;`** ，或任意位置 **`exit(0);`**（需 `<stdlib.h>`） |
| 跳过本轮循环 | `continue` | **`continue;`** |
| 提前跳出循环 | `break` | **`break;`** |
| 断言 | `assert 条件` | **`assert(条件);`**（需 `<assert.h>`；定义了 `NDEBUG` 就失效） |

⚠️ **关键澄清**：**`return` 退出的永远只是"当前这个函数"**。
- 在 `main` 里 `return 0;` → 退出**整个程序**（这就是练习3-5 那招为什么管用）
- 在 `fact()` 里 `return f;` → 只回到调用它的地方，程序继续跑

### 三、防御性编程的 5 个 C 套路

**① 入口卫语句（最常用）**：把非法输入在开头一次赶走，后面主逻辑就能"一条直线"写。

```c
if (year < 2001 || year > 2100)
{
    printf("Invalid year!\n");
    return 0;                 /* 后面的逻辑一律不用想它 */
}
```

**② 检查 `scanf` 的返回值**（这就是 `-Wall` 报的那个 `warn_unused_result`）

```c
if (scanf("%d", &year) != 1)   /* 输入不是数字 → 读失败 */
    return 1;
```

**③ 访问前先判边界**（和 LeetCode 88 的护栏同一条，靠 `&&` 短路）

```c
if (i >= 0 && i < n && a[i] == target)   /* ✅ 越界判断写在左边 */
```

**④ 除法/开方前查非法**

```c
if (n > 0)  printf("average = %.1f\n", (double)sum / n);
else        printf("average = 0.0\n");            /* 除零保护 */
```

**⑤ 兜底分支别省**

```c
if (...) { }
else if (...) { }
else { }                 /* 用 else 兜底，而不是留漏洞 */
```

### 四、心法

> **防御性编程 = 在函数入口，把所有"不可能的情况"先赶走；然后主逻辑假装它们不存在。**
> 判据：**"如果用户给我一个完全不合法的输入，我的程序会怎样？"** 答不出来 → 就还没防御。

### 五、免费的静态防御：`-Wall -Wextra`

编译器能替你抓住一批"用之前没初始化""少 return""格式串不匹配"——**这些就是最便宜的防御性检查**，比事后 debug 便宜 10 倍。

## 🗃 变量的两种角色：暂存格 vs 累积器（2026-10-28 建）

> 触发点：练习4-10 我自己的话——**"暴露了一个问题：我不知道一个变量可以被反复输入。"**
> 因为不知道 `scanf` 能反复覆盖同一个变量，就以为"必须先把所有数存起来"。

### 一、一个变量可以被反复覆盖

```c
int x;
for (int i = 0; i < n; i++)
{
    scanf("%d", &x);        /* 每次都是同一个格子，新值【覆盖】旧值 */
    if (x < min) min = x;   /* 旧值丢了也没关系 —— 我要的只是"目前最小" */
}
```

> **能这么干的前提只有一个：你不需要旧值。**

### 二、两张表（这是本质）

| 类型 | 行为 | 例子 | 为什么需要 |
|---|---|---|---|
| **暂存格** | **每轮被覆盖**，只服务当前这轮 | `int x; scanf("%d", &x);` | 用完即弃 |
| **累积器** | **跨轮保留**，把历史压进一个数 | `sum`、`min`、`count`、`term`、`found` | 需要"历史的一个摘要" |

| 我要的东西 | 用什么 | 要数组吗 |
|---|---|---|
| 当前这个数（马上判断） | 暂存格 | ❌ |
| 总和 / 最值 / 个数 / 标志 | 累积器 | ❌ |
| **列出全部 / 排序 / 第 k 名 / 回头对比** | 累积器不够 → **必须存历史** | ✅ |

> **判据**：**"我要记住的是「一个摘要」，还是「每一份原始数据」？"** 摘要 → 累积器；原始数据 → 数组。

### 三、和旧知识的连接

- `=` 是**覆盖**（10-24 数值积分学过 `=` vs `+=` 的存钱罐比喻）——`scanf` 覆盖是同一个机理，只是新值来自键盘。
- 这也是"**边读边算** vs **存数组**"判据的底层原因：能不能边走边忘。

## 🚨 老毛病 #1：让一个变量干两件事（**跨三门课的同一个病**）

> 2026-10-24 我自己点出来的："我让 i 干两件事是我的老毛病了。"
> 查了一遍历史记录，**这不是 C 的问题，是贯穿高数、Python、C 的一个习惯**。

**病根一句话**：
> **一个变量同时扮演两个角色，而这两个角色的数值并不同步 → 必然错，而且编译器不报错。**

### 证据链（同一模式，7 次）

| # | 学科 / 场景 | 一个变量当了哪两个角色 | 后果 | 出处 |
|---|---|---|---|---|
| 1 | 高数 T5 梯度下降 | `x` 既当"位置"又当"循环计数" | 覆盖起点、迭代乱掉 | 10-01 |
| 2 | 高数 T6 牛顿法 | `for x in range(1,6)`：`x` 被 range **每轮重置** | 根本不迭代，输出不收敛 | 10-02 |
| 3 | LeetCode 26 | `k` 同时当"看"（右手探路）和"放"（左手写入） | 整个思路从前提上跑偏 | 10-07 |
| 4 | LeetCode 118 杨辉三角 | 外层变量（管哪一行）和内层变量（管这一行第几对）**套反** | `mid` 跨行累加、输出错乱 | 10-11 |
| 5 | C 练习2-14 | `i` 既当"第几项"又当"分母上限" | 23 项只加了 12 项 | 10-24 |
| 6 | C 练习2-15 | `i` 既当"第几项"又当"分母" | 分母 1,4,7 根本写不出来 | 10-24 |

> ⚠️ **勘误（2026-10-29）**：原先这里还记了"C 习题3-2：`m`/`n` 车速/限速用反"——**这条是错的，已删除**。
> 题面输入顺序是「**车速 限速**」，我当时误当成"限速 车速"，于是把他**正确**的 `x = (m-n)*100/n`（m=车速、n=限速）判成了"反了"。3-2 真正的问题是 `%` 未转义、边界 `x <= 50`、缺 `\n`。
> **教训（对我自己的）**：给结论前先要题面原文；模型会用自己的假设填补缺失信息。

### 判据（写循环前，强迫自己问一句）

> ## **"这个变量是【数数的】，还是【被算的】？"**
> **两个角色 → 两个变量。**

| 情况 | 解法 | 例子 |
|---|---|---|
| 两个角色**不同步**（1,2,3… vs 1,4,7…） | **拆成两个变量** | `k` 数项 + `den` 走分母 + `den += 3` |
| 一个是另一个的**函数**（分母 = 3k−2） | 只留一个，另一个**用公式算** | `1.0 / (3 * k - 2)` |
| 两个角色**同步**（N 项且分母到 N） | 可以合并，但**要在注释里写清** | 2-13 的 `1.0 / k` |

### 为什么这个毛病特别难改

1. **编译器永远不提醒**——它不报错、不警告，甚至给你一个"看起来合理"的答案。
2. **省变量看起来更聪明**——少写一个变量像个"优化"，其实是在埋雷。
3. **它跨语言、跨学科复发**——换了语言、换了科目，习惯还在。

### 落地的两个动作

- **写循环前先写一行注释**，把每个变量的角色钉死：
  ```c
  /* k = 第几项（计数器）;  den = 分母（每次 +3） */
  ```
- **答案不对时，第一个查的不是公式，是"有没有变量在兼职"**。

## 🚨 老毛病 #2：设了状态变量，却忘了更新它

> 2026-10-24 我自己总结："我写了 `sign`，但是忘记更新状态。"

**病根**：**声明了、给了初值、也在用——就是没让它每轮变化。** 初始化写了，更新漏了。

### 证据链

| # | 场景 | 设了初值 | 漏了更新 | 后果 | 出处 |
|---|---|---|---|---|---|
| 1 | LeetCode 26 删除重复项 | `k = 0` | `k += 1` | 慢指针不动，所有元素被覆盖到同一格 | 08-11 / 10-07 |
| 2 | C 习题2-4 交错序列 | `int sign = -1;` | `sign = -sign;` | 第 2 项起永远同号 → `0.917` 变 `-2.050` | 10-24 |

### 判据：每个状态变量问三句

> 1. **初值是什么？** → 累加 `0`、累乘 `1`、符号 `+1`、指针 `0`/`len-1`
> 2. **每轮怎么变？** → `S += …`、`p *= …`、`sign = -sign`、`k += 1`、`den += 3`
> 3. **什么时候停？** → `i <= N`、`l <= r`、`n > 0`

**三句里"每轮怎么变"最容易漏**——所以写完循环，专门扫一遍：
> **"我用的每一个状态变量，循环体里有没有一行在改它？"**
> 没被改的，要么它是常量（那没事），要么就是漏了（这就是 bug）。

## 🚨 老毛病 #3：算的是 A，用的却是 B

> 2026-10-28 自己踩的：练习4-7（e 的近似值）里 `count /= i;` 算对了，**下一行却写 `sum += i;`**（加了索引，没加刚算出来的那项）。

**病根**：**辛苦算出来的值晾在一边，顺手拿了旁边那个变量**——而且编译器永远不报错。

### 证据链（2 次）

| # | 场景 | 算的是谁 | 用成了谁 | 后果 | 出处 |
|---|---|---|---|---|---|

### 自查句（写完"用值"的那一行，花 3 秒）

> **"我现在加（乘/比较）的这个变量，是刚才算出来的那个吗？"**
> 不是 → 要么改用它，要么你根本不需要算上一步。

### 根因之一：**变量名在骗人**

| 我起的名字 | 它其实是 | 更好的名字 |
|---|---|---|
| `count` | 当前这一项的值（1/i!） | **`term`** |
| `m`, `n`（3-2 里） | 车速、限速（**题面输入顺序是「车速 限速」**） | **`speed`, `limit`** |
| `den` | 阶乘 / 分母 | **`fact`** / `den`（别一物两用） |
| `V`, `L`（3-2 里） | 车速、限速 | 可以，但 `speed`/`limit` 更好读 |

> **名字起错，自己都会被骗。** 命名时就问："**它代表什么**"——不是"它现在叫什么方便"。

### 🧭 附：「我老是粗心大意」这个结论不成立（2026-10-28 记）

| # | 我写错的样子 | 正确写法 | 为什么 / 一句话记法 | 出处 |
|---|---|---|---|---|
| 1 | `double S += 1.0 / N;` | `double S = 0.0;`，循环里再 `S += ...` | **声明只能接 `=` 初值**；`+=` 是对"已经存在的变量"做累加。**声明和累加是两件事，不能合成一句**（编译直接报 `expected '=' before '+='`） | 10-24 练习2-13 |

| 12 | 声明 `int N;` 却写 `for (i = 0; i < n; i++)` | 全程统一一个写法（就用 `N`） | **C 区分大小写**：`n` 和 `N` 是两个不同的变量 → `error: 'n' undeclared`。这类错误**编译器第一条就点出来了**，别慌，直接看它说哪个名字 | 10-24 练习3-3 |

| 15 | **循环里的 `printf` 忘了 `\n`**：`printf("price = %.2f", price);` | `printf("price = %.2f\n", price);` | **多次输出会挤成一行** → 判题机逐行比对 WA。<br>**1 秒动作**：只要 `printf` 在循环里，先问"**这些结果是一行一个，还是拼成一整行？**" 一行一个 → 必须 `\n`。题目出现"逐行 / 每行 / 各占一行"就是信号 | 10-25 练习3-5 ／ 10-26 练习3-8（**两天内复发**） |
| 16 | 找最小值/最大值时，`int min = 0;` 当初始值 | **先读第一个数当基准**：`scanf("%d",&x); min = x;` 再从第 2 个开始比（或用 `INT_MAX` + `<limits.h>`） | **初值必须来自真实数据**。设 0 的死穴：**全是正数时输出 0**（`5 9 3` → 输出 0，应 3）。Python 的 `min(list)` 自动处理了这件事，C 没有 ⇒ 得自己挑一个"真实存在"的初值 | 10-28 练习4-10 |
| 17 | 抄改代码时**只换循环体，留着旧初值**：`sum = 0.0` 配"从 1 开始、首项靠初值"的写法 | `double sum = 1.0;`（第 0 项 = 1/0! = 1） | **初值是结构的一部分**。递推四件套 `sum=1` / `term=1` / `term/=i` / `sum+=term` 是一整套，换一半必错。结果特征：**每个 n 都差同一个常数** ⇒ 十有八九是初值 | 10-28 练习4-7（差 1.00000000） |

### 🔍 三条检查动作（比"多检查一遍"具体）

1. **编译必须开 `-Wall`**，warning 一条都别滑过去——第 3、8 条都是它先发现的。
2. **对齐/空格类问题，用方括号打印出来看**：`printf("[%6.1f]\n", x);`
3. **自己造极端输入**：负数、边界值、最短/最长、单行——样例永远只给你最舒服的那组。
4. **输出格式别手打，从题面复制**：`letter` / `Invalid.` / `average = ` 这些词和符号，复制粘贴比凭记忆敲稳——**逻辑全对、一个字母拼错，照样 0 分**（10-25 练习3-4 就栽在这里两次）。

## 🖨️ printf 格式串速查（**不用背，查这个** · 2026-10-24 建）

> 触发点：10-24 做 2-12 时"占位符掌握不完全"，把 `%d   %.1f`（手打空格）当成对齐办法。

**占位符 = 格式说明符 = 一个挖好的坑，运行时把值填进去。它是四个槽位拼出来的：**

```
%        6        .1        f
│        │        │         │
①开关   ②最小宽度 ③小数位数  ④类型
```

| 写法 | 打印效果 | 用在什么场景 |
|---|---|---|
| `%d` | `32` | 普通整数 |
| `%5d` | `[   32]` | 整数占 5 宽、靠右 |
| `%-5d` | `[32   ]` | 靠左 |
| `%05d` | `[00032]` | 补零 |
| `%f` | `1.111000` | 浮点默认 **6 位小数** |
| `%.1f` | `1.1` | 只限小数位数，不占宽 |
| **`%6.1f`** | `[   1.1]` | **占 6 宽 + 1 位小数、靠右（2-12 用这个）** |
| `%-6.1f` | `[1.1   ]` | 同上去左对齐 |
| `%c` | `A` | 单个字符 |
| `%s` | `hello` | 字符串 |
| **`%%`** | `%` | **打印一个真实的百分号** |

### 三条铁律

1. **个数和类型必须一一对应**：占位符几个、参数几个，顺序和类型都要对上。错一个 → 打印垃圾，**而且不一定报错**（3-2 的 `%.L` 被读成 `%Li` 就是这么来的）。
2. **`%%` 才是字面上的 `%`**：格式串里 `%` 是"开关"，后面紧跟的字会被当成指令吃掉。
3. **宽度是"最小"宽度，不是固定宽度**：值比它还长就整个打印出来，**不截断、不错位**。

### 空格怎么数（比背规则可靠）

> **要补的空格数 = 宽度 − 值本身占几个字符**
> 例：`%6.1f` 打印 `-17.2` → 值占 **5** 个字符（`-17.2`）→ 补 **1** 个空格。
> 记牢两点：**负号算一个字符**；**小数点算一个字符**（但不算"一位数字"）。

### 自查动作（数不准时别猜）

```c
printf("[%6.1f]\n", 123.4);   /* 用方括号把空格框出来，一眼看清 */
```

## ⚖️ 逻辑运算符 and / or / not（Python ↔ C 对照 · 2026-10-25 建）

> 触发点：练习3-4 把 `c == ' ' || c == '\n'` 写成 `&&`，理由是"中文里说空格和回车"。
> **`&&` 没记错，错在中文的"和"被直接翻译成 and。**

### 一、对照表（这是最容易混的一张）

| 逻辑 | **Python** | **C** | 说明 |
|---|---|---|---|
| 与（都要满足） | `and` | **`&&`** | 左真**且**右真，才真 |
| 或（满足一个） | `or` | **`\|\|`** | 左真**或**右真，就真 |
| 非 | `not` | **`!`** | 取反 |

> ⚠️ Python 里写 `&&` 是语法错误；C 里写 `and`/`or` 也不是标准写法（有 `<iso646.h>` 的宏，但学校不用）。**两个语言的词不通用。**

### 二、真值表（背不下来就现场代值）

| A | B | `A && B` | `A \|\| B` | `!A` |
|---|---|---|---|---|
| 真 | 真 | 真 | 真 | 假 |
| 真 | 假 | **假** | 真 | 假 |
| 假 | 真 | **假** | 真 | 真 |
| 假 | 假 | 假 | 假 | 真 |

**C 里"真/假"就是数字**：非 0 = 真，0 = 假。所以 `3 && 5` 是真，`if (5)` 永远成立。

### 三、中文怎么翻（这是真正的坑）

| 题目/脑子里的中文 | 逻辑 | C 写法 |
|---|---|---|
| 是空格 **或** 是回车（二选一） | 满足任一 | `c == ' ' \|\| c == '\n'` |
| 空格 **和** 回车**都算**（列举身份） | 满足任一 | 还是 `\|\|` |
| 既 ≥ 'A' **且** ≤ 'Z'（同时成立） | 都要满足 | `c >= 'A' && c <= 'Z'` |

> **判据**：说的是"**几个可能的身份**"（空格／回车／Tab）→ `||`；说的是"**几个必须同时成立的条件**"（既大又小）→ `&&`。
> **验算**：拿一个具体值代进去（`c = ' '` → `&&` 立刻变假，一眼看穿"分支永假"）。

### 四、短路求值（和 LeetCode 88 的护栏经验是同一条）

**`A && B`：A 为假就 **不看 B**，直接判假。**`A || B`：A 为真就不看 B。**

→ 所以"**先判越界、再访问**"时，**护栏必须写在左边**：

```c
if (m > 0 && nums1[m-1] > nums2[n-1])   /* ✅ m==0 时短路，右边不算 */
if (nums1[m-1] > nums2[n-1] && m > 0)   /* ❌ 危险访问先发生了，护栏来晚了 */
```

> 这条我在 LeetCode 88 上栽过一次（写成 `elif` 无护栏 → 死循环），在 C 里是**同一条**，只是符号从 `and` 变成 `&&`。

### 五、三个必避的坑

| ❌ | 后果 |
|---|---|
| `c == ' ' & c == '\n'`（单 `&`） | `&` 是**位运算**，不是逻辑与 → 不报错、语义完全变 |
| `if (x = 5)`（赋值当比较） | 恒真；应为 `==` |
| 不加括号：`a && b \|\| c` | 优先级 `!` > `&&` > `||`，能背但容易错 → **宁可多写一对括号** |

### 六、优先级（从高到低）

```
!  →  &&  →  ||
```
不放心就加括号：`(a && b) || c`。**括号不扣分，逻辑错才扣分。**

## 🌊 输入模型：C 没有"行"，只有**字符流**（2026-10-25 建）

> 触发点：练习3-4 看不懂 `char c = getchar();` 在循环里到底取到了什么；并且**和蓝桥杯的 Python 输入模型混了**。

### 一、两套模型，别混

| | **Python（蓝桥杯笔记里那套）** | **C** |
|---|---|---|
| 读入单位 | **一行**：`input()` 读一整行（不含行尾换行） | **一个字符**：从流里取，**没有"行"这个概念** |
| 空白怎么办 | `split()` 按空白切分 | `scanf("%d")` 自动**跳过**空白；`getchar()` / `%c` **不跳** |
| 换行是什么 | 行的边界，`input()` 自动处理掉 | **一个普通字符**（`\n`，编码 10），会被读进来 |
| 读完拿到什么 | 一行**字符串**，再加工 | 从队头**取走**若干字符 |

### 二、C 的心智模型：一条字符队列

输入 `aZ &⏎09 Az⏎` 在 C 眼里是这样一串：

```
[a][Z][ ][&][\n][0][9][ ][A][z][\n]
 ↑ 每次 getchar() 从队头取走 1 个字符，谁都不例外
```

**实测**（2026-10-25 真跑的，`getchar()` 逐轮取到的东西）：

```
第 1轮 [a]97   第 2轮 [Z]90   第 3轮 [ ]32   第 4轮 [&]38    第 5轮 [\n]10
第 6轮 [0]48   第 7轮 [9]57   第 8轮 [ ]32   第 9轮 [A]65    第 10轮 [z]122
```

→ 第 5 轮那个 `\n` 就是**第一行末尾的回车**，它被当成一个字符读走了。

### 三、谁会"跳过空白"（这张表是全部）

| 写法 | 跳空白？ | 取到什么 |
|---|---|---|
| `scanf("%d", &x)` | **跳** | 一个整数（前面的空格/换行自动跨过） |
| `scanf("%s", s)` | **跳** | 一串非空白字符，**遇空格就停** |
| `scanf("%c", &c)` | **不跳** | 1 个字符（空格、回车都原样给你） |
| `getchar()` | **不跳** | 1 个字符（和 `%c` 等价，写法更短） |

> **一句话判据**：要**数字** → `scanf("%d")`；要**看见空白字符**（统计空格/回车、逐字符处理） → `getchar()` / `%c`。

### 四、蓝桥杯「四种读入形态」的 C 版对照

| 形态 | Python 版（我笔记里） | **C 版骨架** |
|---|---|---|
| **A 单行一个数** | `int(input())` | `scanf("%d", &n);` |
| **B 两行：n + n 个数** | `n = int(input())` + `split()` | `scanf("%d",&n); for (i=0;i<n;i++) scanf("%d",&a[i]);` |
| **C 多行矩阵** | 嵌套 `split()` | 先 `scanf("%d",&n)`，再**双层 for** 读 `a[i][j]` |
| **D 多组 / 读到结尾** | `while True: try: input()` | `while (scanf("%d", &n) == 1) { … }` 或 `!= EOF` |

> ⚠️ **C 里 `scanf("%d")` 天生就替你做完了 Python 里 `split()` 干的活**（跳空白、按空白一个个取），所以四种形态在 C 里反而更短。**唯一的例外是"要读空白本身"**——那时必须换成 `getchar()`。

### 五、连带坑

- **`scanf("%d")` 之后紧跟 `scanf("%c")`**：数字读完后输入里残留的那个回车，会被 `%c` 吃掉 → 看起来"凭空多读到一个字符"。
- 练习3-4 没有数字输入，所以安全；但**混读**（先读 n 再读字符）时一定会撞上。

### 六、`getchar` 到底是什么（2026-10-25 补）

**它不是关键字，是 `<stdio.h>` 里的库函数**（和 `printf`/`scanf` 同一个头文件）。

```c
int c = getchar();
│    │       └── 括号里什么都不写（无参数），但【括号不能少】
│    └────────── 返回值是 int，不是 char！
└─────────────── 需要 #include <stdio.h>
```

| 点 | 细节 |
|---|---|
| 无参数 | 写 `()`；`getchar(c)` 是错的 |
| **括号不能省** | `c = getchar;`（无括号）不是调用，是"函数地址" |
| **返回 `int`** | 为了能返回 **`EOF`（-1）** 表示"输入结束"；`char` 装不下 -1 |

**为什么必须是 `int`**：读到结尾时返回 `EOF`（-1）。用 `char c` 时 -1 会变成 255 → `c != EOF` **永远成立** → 死循环。练习3-4 只读 10 个字符，`char` 能过，但**标准写法是 `int c`**。

> ⚠️ **隐式类型转换（这是"能过但不严谨"的典型）**：`char c = getchar();` 编译**不报错、`-Wall` 也不警告**（要 `-Wconversion` 才警告）——C 自动把 int 截断成最低 8 位。**只有"值装不下"时才出事**（如 -1）。同类危险型号：整数除法、`%f` 打印大数、`(int)` 强转大阶乘。
>
> **结论**：要判断 `EOF` → 必须 `int`；只读固定几个字符 → `char` 也行（教科书也这么写）。**自己写统一用 `int c`，不亏。**

**输入输出家族**：`getchar()` 读 1 字符 ｜ `putchar(c)` 输出 1 字符 ｜ `scanf`/`printf` 格式化 ｜ `fgets` 读一行（以后学文件）。

**标准循环写法**（双括号是必须的）：

```c
int c;
while ((c = getchar()) != EOF) { … }     /* 读完全部输入 */
while ((c = getchar()) != '\n') { … }    /* 只读到本行末尾 */
```

> ⚠️ 写成 `c = getchar() != EOF` 会先算 `!=`（得 0/1）再赋值 → **意思完全变了**。又是"`=` 与比较运算符优先级"的坑。

## 🧩 函数语法细节（第 5 章预习 · 2026-10-24）

> 触发点：练习2-18 里写了 `fact(n)` 却没定义它 → 编译报 `implicit declaration of function 'fact'`。
> **动机**：先把"函数长什么样"钉死，等老师讲到第 5 章时我只需要补"为什么"。

### 一、先认清：你早就在写函数

```c
int main(void)
│    │     └── 参数表：void = 不要参数
│    └──────── 函数名
└───────────── 返回类型
```
`main` 就是一个函数而已——**返回 `int`、不收参数、名字叫 main**。

### 二、解剖一个函数（每个零件都标了）

```c
double      fact  ( int n )      /* ① 返回类型  ② 函数名  ③ 参数表（形参） */
{                                /* ④ 函数体开始 */
    double f = 1.0;              /*    局部变量：出了这个函数就消失 */
    for (int i = 2; i <= n; i++)
        f *= i;
    return f;                    /* ⑤ 把 f 交回调用处，并【立刻】结束函数 */
}                                /* ⑥ 函数体结束 */
```

| 零件 | 规则 |
|---|---|
| **① 返回类型** | 交回什么类型的值就写什么：`int` / `double` / `char`；**不返回任何东西写 `void`** |
| **② 函数名** | 自己起，**不能和库函数重名**（`pow`、`sqrt` 都不能用） |
| **③ 参数表** | 每个参数都要 **类型 + 名字**（`int n`）；多个用逗号；没有参数写 `(void)` 或 `()` |
| **④ 函数体** | `{}` 里就是普通的语句——循环、判断、printf 全都能写 |
| **⑤ `return`** | ① 结束函数 ② 把值交回。**非 `void` 函数必须保证每条路径都有 return** |

### 三、怎么调用

```c
double r = fact(5);      /* 实参 5 复制给形参 n */
```

- **按位置传**，不是按名字：`fact(5)` 里 5 给第一个参数。
- **形参是副本**：函数里改 `n`，`main` 里的 `n` 一点不受影响。（这条以后会变成"指针"那一章的引子。）

### 四、定义 vs 声明（最容易混）

| | 写法 | 意思 |
|---|---|---|
| **定义** | `double fact(int n) { … }` | 有函数体，真的干活 |
| **声明（原型）** | `double fact(int n);` | **只有头 + 分号**，告诉编译器"有这么个函数" |

**顺序规则**：函数要么**定义在 main 前面**，要么在 main 前面**写原型**。否则就是我今天犯的错：`implicit declaration`。

### 五、常见错误（对号入座用）

| ❌ 写法 | 现象 |
|---|---|
| `fact(int n) { … }`（少返回类型） | C99 起报错（不写就是违规） |
| 非 void 函数**漏 `return`** | 返回一个垃圾值，不报错 |
| `double fact(int n);` 后面又写 `{ }` | 那是"声明之后再定义"，合法但重复 |
| 定义时**忘了参数类型**：`double fact(n)` | 报错 `expected declaration specifiers` |
| **在 main 里面定义函数** | **C 不支持嵌套函数** |
| 调用时忘括号：`fact` | 那不是调用，是"函数地址" |
| 以为按名字传参 | C **只按位置** |

### 六、和三件旧事的联系

1. **局部变量作用域**：函数里声明的变量出了函数就没了——和"循环体里声明"是同一条规则。
2. **递归**：函数调用自己。我在 Python 509 学过"**出口 + 递推关系**"，C 里一模一样（出口 = `if (n <= 1) return 1;`）。
3. **累乘/累加**：`fact` 内部就是 `f = 1.0` + `f *= i`——今天已经写过 4 遍的东西。

> 📌 一句口诀：**返回什么、叫什么、吃什么** —— 返回类型 / 函数名 / 参数表。写函数先在心里说这三句，语法就不会错。

## ➗ 数列通项怎么读（等差 · 2-13~2-15 连考三题的共同技能）

> 触发点：2-15 把分母写成 `i + 3`（得到 4,5,6,7…），抄了上一题的形状，没读题目给的数列。

**一条公式**：`a_k = 首项 + (k − 1) × 公差`

| 分母序列 | 公差 d | 通项 | 出处 |
|---|---|---|---|
| 1, 2, 3, 4 | 1 | `k` | 2-13 |
| 1, 3, 5, 7 … | 2 | `2k − 1` | 2-14 |
| 1, 4, 7, 10 … | 3 | `3k − 2` | 2-15 |
| 2, 4, 6, 8 | 2 | `2k` | — |
| 1, 3, 5, 7, 9（分子也是 k） | 2 | `2k − 1` = **2×分子 − 1** | 2-4 |

**三题的模板完全一样，只有通项不同**：

```c
for (int k = 1; k <= N; k++)      /* N 永远 = 项数 */
    S += 符号 * 1.0 / (通项);
```

- 2-13：通项 `k`，全正 → `1.0 / k`
- 2-14：通项 `2k-1`，全正 → `1.0 / (2*k-1)`
- 2-15：通项 `3k-2`，**交错** → 用 `sign` 变量，`sign = -sign`

### 两种写法都能写出来，选一个趁手的

**写法 ①：分母自己每次 +公差（两个变量，最直观）**
```c
int den = 1;                   /* 分母：1,4,7,10… 自己递增 */
for (int k = 1; k <= N; k++)   /* k 只负责"数到第几项" */
{
    S += sign * 1.0 / den;
    sign = -sign;
    den += 3;                  /* ← 每轮 +3 */
}
```

**写法 ②：用通项算（一个变量，更短）**
```c
for (int k = 1; k <= N; k++)
    S += sign * 1.0 / (3 * k - 2);
```

> 💡 **不想推公式时，用递推绕过去**：写法 ① 里分母自己 `den += 3`，**通项公式一个都不用想**。
> 递推和通项是同一件事的两种写法；只有当"**分子分母联动**"（如 2-4：分子 `i`、分母 `2i−1`）或需要"跳着取第 k 项"时，才必须写通项。

> ⚠️ **别让一个变量同时干两件事**：`i` 既是"第几项"（1,2,3…）又是"分母"（1,4,7…）——这两个数不同步，所以必然错。要么分成两个变量（写法 ①），要么用一个、另一个用公式算（写法 ②）。

**最便宜的探针**：先跑 `N = 1`，输出必须等于第一项（2-15 应为 `1.000`）。错在这一项，后面全错。

### 📅 2026-10-25 · 第 3 章（练习3-4 统计字符 + 练习3-5 输出闰年）

**🎯 今天搞懂的一件事**：**C 没有"行"，只有一条字符流**——`getchar()` 从队头取走一个字符，空格和回车都是普通字符；想要"取数字"才用 `scanf("%d")`（它会自动跳过空白）。

**1. 核心概念（我现在理解的）**
- **输入模型**：`getchar()` 逐个取字符（空白也取）；`scanf("%d")` 自动跳空白；`scanf("%s")` 遇空格就停。
- **`getchar()` 是库函数**（`<stdio.h>`），无参数、括号不能省、**返回 `int`**（为了能返回 `EOF`）。
- **`&&` = 都要满足；`||` = 满足一个**。真正的坑在中文："空格**和**回车都算"是**列举**，对应 `||`。
- **整除看余数**：`i % 400 == 0`；`i / 400 != 0` 是"商不为 0"，恒真。
- **防御性编程（C 版）**：入口卫语句 `if (非法) { 打印; return 0; }`；`main` 里的 `return 0;` 就等价于 Python 的"立刻结束"。

**2. 我在习题里踩的坑**
- 3-4：`c == ' ' && c == '\n'`（互斥条件用了 `&&` → 分支永假，`blank` 恒 0）；输出把 `letter` 拼成 **`leeter`**（统计全对，照样 WA）。
- 3-5：`i / 400 != 0` 当整除用；循环从 **2000** 起（2000 是闰年 → `found` 永远为 1 → **`None` 分支全废**）；`printf("%d", i)` 缺 `\n`；**忘了防"非 21 世纪"**（→ 补了卫语句）。
