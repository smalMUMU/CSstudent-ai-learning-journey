## 📏 冷写规矩

1. **不看代码、不看日志、不看速查表、不问我**（看了一样 = 不算冷写）。
2. **限时**：单文件 ≤ 20 分钟；带类/带服务 ≤ 30 分钟。超时也算没通过。
3. **先跑探针自检**：造 1 个小输入（空 / 1 个 / 边界），看结果对不对，再提交。
4. **过 = 独立编译运行成功 + 能讲清关键那几行为什么**。
5. **没过也照记一行**，写清"卡在哪"——这比"过了"值钱。
6. **顺延规则**：当天有课/忙，最多顺延 2 天。超 1 周就从"复习"变成"重学"，成本翻倍。

## 📝 变体题库（我出，答案自己推）

> 用法：**冷写通过之后**才做变体——变体验"迁移"，不验"记忆"。

| 对应的交付 | 变体 |
|---|---|
| G0 | 从命令行参数读名字，输出 `Hello, <名字>`（练 `String[] args`） |
| G1 | 词频统计改成：**按次数排序输出**，或**只统计每行前 3 个词** |
| G2 | `/hello` 改成：`/hello?name=xxx` 返回带名字的 JSON（练 query 参数） |
| G3 | 查询改成：`/users?age=20` 按条件过滤（练 `WHERE` + 参数绑定） |
| G6 | 挑一个功能点问自己：**"这块换成 B 技术会怎样？"**（这就是面试问法） |

## 🔁 没通过怎么办（不重刷整题）

1. **先把"卡在哪一行"写进 `复习总结/Java每日总账.md`**。
2. 判定属于哪一类：
   - **语法不会** → 补 `Java学习日志.md` →「⛏️ 语法细节清单」
   - **概念没内化** → 补 `Java速查表.md` → 对应栏目 + 复述一遍
   - **会但没执行**（手滑 / 漏 `;` / 大小写） → 定一个 **30 秒固定动作**
   - **交付没入口**（写完了没跑、没留痕） → 直接进交付台
3. **只补那一条，不整题重做**（整题重做收益递减——这在 LeetCode 记录里已经验证过）。
