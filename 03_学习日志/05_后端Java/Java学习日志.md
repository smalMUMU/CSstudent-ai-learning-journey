## 🤝 协作协议（我问 Java 的时候照这个走）

1. **先写后问**：习题先自己动手，卡 20 分钟以上再问；**不让教练第一个写**。
2. **只给零件，不给整车**：教练给我 ①考点 ②提示/思路 ③**哪一行错、报错怎么读**。**不写完整代码**，除非我明确说"给代码"。
3. **讲完必须过两关**：用自己的话**复述** → **关掉重写**一遍、编译跑通。
4. **判据 = 配对测试**（我自己提的）：当下写得出 ≠ 会；**隔 3 天不看还能写**才算会（见 `冷写日程.md`）。
5. **结论落盘**：每条卡点和纠正写进这个文件。
6. **报错只读第一条**：Java 的异常栈比 C 长得多，**第一条 `Exception` + `at` 里最靠上、属于我自己写的那个类那行**才是病因，后面全是连锁。
7. **30 秒自查优先**：初值、边界、分号/大括号、方法名大小写 → 先自己试，别直接问。
8. **贴代码时加一行「我试过什么」**。
9. **先搜再问**（2026-11-05 加）：卡住时先贴三样——**① 我搜了什么关键词 ② 找到什么 / 没找到什么 ③ 我试了哪一版**。三样都没有，教练只回一句"先去搜"。
   - 理由：我四个月的记录里**全是"问教练"，没有一条"我搜到 X"**——这是"懂搜索"的空白，而版本、依赖、报错这类问题，后端比算法更依赖搜索。
10. **每看完一块，必须结算**（2026-11-05 加）：一段课看完，**当场留一个可验证的东西**——跑通的一段代码 / 一句答得出的自测题 / 交付台上往前一格。
    - ❌ 不许"先看完 10 集再一起补"（这是我自己写过的最大风险：**视频最容易变成囤课**）。
    - 结算不了 → 这一块记为 🔶，写清卡在哪一行，然后继续往下（别死磕，也别假装看过）。
11. **教练说话必须有事实依据**（2026-11-06 加，起因是我踩的一次幻觉）：评价我的代码/输出前**必须先读原文**；说事实要指得出「文件+行号 / 命令输出 / 文档」；指不出就标"我猜"并给验证方式；**不知道就说不知道**。
    - 全文见 `04_参考资料/与AI协作原则.md` →「事实纪律」（含反面例子留档）。
    - 我这边只做一件事：**看到教练在评价我没贴过的东西，直接问"你读了哪一行"**。
12. **读我的代码时，注释算正文**（2026-11-09 加）：我的注释里写着他必须回应的三类东西——**① 我的疑问（"满不满足四舍五入呢，暂时不知道"）② 我的结论（"溢出会报错"）③ 我的待办诉求（"Scanner 不熟悉，需要强化"）**。

## 🧨 Java 高频坑（思路 / 边界类 · 踩到才写）

| 类别 | 我踩的现象 | 一句话记法 |
|---|---|---|
| 值 vs 引用 | `int b = a` 改 `b` 不影响 `a`；`int[] y = x` 改 `y[0]` 会影响 `x[0]`——结果答对了，**原因说不出**（11-05 起点诊断，凭 C/Python 直觉） | 基本类型 = **复制值**；数组/对象 = **复制引用**（两张纸条指着同一个盒子） |
| `==` vs `equals` | 说不出两者各比什么；`"hi" == "hi"` 为什么可能为 true 不知道（11-05） | `==` 问"是不是**同一个东西**"；`equals` 问"**内容**一样吗"。字面量在**常量池**里是同一个对象 ⇒ `new String("hi") == "hi"` 为 false |
| String 不可变 | 只知"是拼字符串"，不知 `s += "x"` 其实是**新建对象**（11-05） | String 创建后不可改；`s += x` = 造一个新串再让 `s` 指向它，旧串留给 GC |
| 数组越界 | 不知道 `int[] a = new int[3]; a[3] = 1;` 报什么（11-05） | **编译期不查下标，运行期抛 `ArrayIndexOutOfBoundsException`**（长度可能来自输入，编译期不知道） |
| **整数除法 / 类型提升时机** | 以为 `double d = 5 / 2;` 得 `2.5`，实际 `2.0`（11-05 起点诊断栽） | **右边先按自己的类型算完，再赋值**：`5/2` 是 int 除法 = `2` ⇒ `2.0`。要 `2.5` 得写 `5 / 2.0`。⚠️ 与 C 课 `5*(i-32)/9` 是同一个惯性 |
| **变量练习写成"硬编码"** | 公交车练习写成 7 行常量加减（`count += 1; count += 2; …`）。**我的判断：这题考点就是熟悉 `+=` / `-=`，不改**（11-07） | 变量存在的理由 = **数据变了只改一处**。这一半**没练到**，检验点在后面三处：第一次读入数据（`Scanner`）／方法参数／数组——那里如果还写死，就会卡 |
| **整数除法是截断，不是四舍五入** | 自己写"满不满足四舍五入呢，暂时不知道"（11-08 `chuyu.java`） | `10/3 = 3`、`-10/3 = -3`：**两边都是整数 ⇒ 小数部分直接丢弃（向零截断）** |
| **int→byte 溢出不会报错** | 我写"溢出的 int 强转 byte 会报错"——**错**（11-08） | **窄化转换编译器不查范围、运行期也不报错**，只保留低位：`(byte)200 = -56`。**要加括号**（`(byte)(a+c)` 不是 `(byte)a+c`）——这条我自己撞出来是对的 |
| **浮点不精确的真正原因** | 我写"有小数参与运算结果就不准确"——方向对、原因错。**实测（11-09）：`1.1 + 1.01` 打印 `2.1100000000000003`** | 不是"有小数"不准，是**二进制表示不了多数十进制小数** ⇒ `1.1`、`1.01` 存进去时已被截断，相加后误差冒出来（`0.1 + 0.2 != 0.3` 同理）。**钱不能用 `double`**（后端用 `BigDecimal` 或"以分为单位的整数"） |
| **除零的两种行为** | 还没碰过（11-08 记录） | `10/0`（int）→ 运行期抛 `ArithmeticException`；`10.0/0`（double）→ 得 `Infinity`，不炸 |
| **边界差一个等号**（`<` vs `<=`）—— **同一病三次** | ① 11-10 `panduanzhishu04`：`i*i < number` ⇒ 4、9 被判成质数；② 11-13 `panduanzhishu02`（100–200 找质数）：又写成 `j*j < i` ⇒ **121 和 169 漏检**（21 个质数印成 23 个）；③ 同类的还有"改了长度没改边界" | 边界只问一句：**"最边上那个值本身，要不要被检查？"** 要 → `<=`；不要 → `<`。试除上界必须含 `√i`（因为 `i` 可能是完全平方数）。**别用 `Math.sqrt` 做条件**（浮点误差 + 每次重算） |
| **先读后判 → 多给一次机会 / 白读一次** | 猜数字里 `int target = sc.nextInt();` 之后才 `if (count == 3) break;` ⇒ 实际给 4 次机会，第 4 次输入白读（11-10 `caishuzixiaoyouxi05`，**留痕不改**） | **先检查、再干活**（同我 10-23 那条"先验证再操作"）。控制次数的判断必须在读输入之前 |
| **输出变量用错（老毛病 #3 复发）** | 求商余那道：商本该打印 `count`，却打印了除数 `b`——**因样例 `100/10` 商恰好 = 10 = b 而没露馅**（11-10 `shangheyushu10`，**留痕不改**） | **样例通过 ≠ 正确**：换个不整齐的数（7 / 13 / 17）一测就现形。写完"用值"那行问一句"这真是我刚算出来的那个吗" |
| **把 C 的 `int` 返回当布尔用** | `need()` 返回 1 / -1 表示"存在 / 不存在"，调用处再 `if (count == 1)`（11-12 `fangfalianxichunzailianxi07`） | Java 有 `boolean` 就用它：**"有没有" → `boolean`**，方法叫 `contains`、调用处 `if (contains(...))`。同族：`if` 的条件也必须是 `boolean`，不能写 `if (1)` |
| **错误分支没中止 ⇒ 后面打印垃圾值** | ① `lianxixunhuan08` 输入非法时，异常提示后还打印了 `count = 0`（11-10）；② 机票练习座位异常时，除提示外还打印了初始化用的 `price1 = 1`（11-12）。**同一病两次** | **只打印不算处理完**：错误分支里要 `return;`（或 `throw`）截断后面的正常流程。自查句：**"这条异常路径走完，程序还会继续往下跑吗？"** |
| **改了"长度"却漏改依赖它的边界** | 拷贝数组：`new_arr` 长度改成 `to-from+1` ✅，但打印循环还是 `i <= to-from-1` ⇒ 数据对、显示少一个（11-12 `fangfakaobeishuzulianxi08`） | 改一个数之后**搜一遍谁还在用它**；边界别自己推，直接 `arr.length`。同我 LeetCode 记录里那条"数据变短后所有下标都要重算" |
| **`if (条件);` 后面误加分号** | `if (max < scoreArr[i]);` 后面紧跟赋值 ⇒ `if` 变成空语句，赋值无条件执行 ⇒ `max` 最后等于数组**最后一个元素**（11-13 评委打分黑马版）。**编译器不报错** | `if` 后面看到分号就问一句"这是我要的吗"。同族：C 的悬挂分号、`for(...);` 后多分号 |
| **数组类型的 `[]` 有四处** | ① 方法返回类型 `int[] getScores()` ✅；② **接收变量**漏了：`int scoreArr = getScores()` ❌（11-13）；③ 参数类型 `getSum(int[] a)`；④ **调用处不写类型**：`getMax(int[] scoreArr)` ❌ 应为 `getMax(scoreArr)`（11-13） | 记法：**定义时写 `[]`，调用时只传名字** |
| **验证"是不是副本"不能只比内容** | 数组复制的校验只比 `farr[i] != arr[i]`——**如果两变量指向同一个数组，内容当然一样，校验照样通过**（11-13 `shuzuyuansufuzhi04`） | **改一个再看另一个**：`farr[0] = 999` 后 `arr[0]` 若不变 ⇒ 真副本。**测什么，比测出什么更要紧** |
| **方法签名的返回类型 ≠ `return` 的类型**（**同一概念四次**） | ① `int` 方法 `return` 数组（11-12 我自己发现）；② 接收端漏 `[]`（11-13）；③ 抽奖里 `public static int check(...)` 却 `return boolean flag`（11-13） | **签名上的返回类型 = 每处 `return` 后面那个值的类型。** 写之前用方法三问第③问定类型：要判断 → `boolean`；要数组 → `int[]` |

### 🛠️ 最小编译流程（照抄就行，这不属于"代写"）

```
javac Hello.java        # 编译：源码 → Hello.class（字节码）
java Hello              # 运行：JVM 加载字节码执行
javac -encoding UTF-8 Hello.java   # 有中文注释/字符串时加这个，避免乱码警告
```

> ⚠️ 报错只读**第一条**；`java Hello.class` 是错的（运行时**不带** `.class`）。
