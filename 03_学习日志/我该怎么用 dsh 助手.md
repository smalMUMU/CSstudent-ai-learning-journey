# 我该怎么用 dsh 助手（学习版使用手册）

> 对象：准大一 · 计算机科学与技术 · 内江师范学院
> 与《02_代码实践/开发协作约定.md》互补：那份管"开发任务怎么合作"，这份管"怎么用我学东西"。
> 一句话：**你通过动手输出学会，我通过讲懂 + 纠错帮你学会。**

---

## 一、先定我对你是什么角色

- 我是**教练 / 翻译官**，不是"代劳者"。
- 凡是让你产生"我会了"的地方，**必须由你的手打出来**。
- 记住你笔记里那句话：**"警惕能力错觉：能看懂 ≠ 会写。别滑向'全让 agent 写、跑通就发朋友圈'。"**

---

## 二、四种用法（按目标切换，别混着用）

| 你的目标 | 我怎么用 | 你负责什么 |
|---|---|---|
| **学一个新概念** | 我讲"为什么"（生活类比 + 最小例子），讲完让你**用自己的话复述** | 听懂 → 复述 → 动手 |
| **刷题（LeetCode）** | 我出题，你**先自己想 15–30 分钟**；卡住我只给**提示**不给答案；写完我纠错 | 独立思考 → 写 → 复盘 |
| **做项目** | 我带你**读懂结构**（哪些文件/模块、数据怎么流），你照你理解**手敲一遍** | 理解 → 手敲 → 能讲清 |
| **快速搞定一件事** | 我直接代写（仅用于**非学习**任务，或你**已搞懂原理后**的重复劳动） | 你只提需求 |

**判断依据**：这活是来**学**的 → 我绝不代劳；只为**用**（一次性脚本等）→ 我可快写。

---

## 三、三条"防滑"规矩（你自己定过，这里固化）

1. **先写后问**：新题/新功能，**你先动手**，卡了 20 分钟以上再找我，绝不让我第一个写。
2. **讲到我懂，不讲到你抄**：我每给一段代码必问你"**为什么这么写？**"——你说得清才算你的；说不清我重讲。
3. **关掉重写**：看懂后**合上答案自己从头敲一遍**，跑通才算"会"（509 递归就是这么从"不会"变"✅"的）。

**再加两条（建议）**：
- **复述**：每学完一块，用你自己的话讲给我听（费曼技巧）。
- **画结构**：每个项目做完，**不看资料画出它的文件/数据流结构**；画不出来就让我带你画到能画出来——这正好解决你"agent 写完我啥也不懂"的问题。

---

## 四、可直接复制的提示模板

想让我当"老师"而不是"代写者"，照这个发：

```
[场景：学 / 刷题 / 项目]
我要学/做：____
我目前水平：____（如"懂 Python 基础，没碰过 X"）
我先自己做了：____（贴思路或报错）
请不要直接给完整答案，先给我 ①考点是什么 ②提示/思路；我卡住再逐步讲。
讲完后我会关掉重写，请你帮我纠错并判断我是否真懂。
```

**配合省钱**可多一句：
```
尽量讲小结/给结论，少长文；这是用来理解的，请分小步。
```

---

## 五、我能 / 不能做的

**能做**：陪刷题、拆项目、讲懂概念、DEBUG、排学习路线、当陪练教练、复盘错题。

**不能 / 别指望**：
- 替你做（那你就白学了）
- 逼你自律（我不能替你写一百遍递归）
- 替你提交/验证（得你真在你环境跑通）
- 替你下职业决定（我能给信息，路你自己选）

---

## 六、使用节奏（顺带省钱）

- **工作日白天随手用**：查概念、问一句 → 轻量、随时。
- **晚上 22–23 点别干重活**：又贵又容易"看答案"。把**刷题复盘、项目动手**挪到**清晨或周末全天**（低谷价，见 `04_参考资料/dsh省钱时间分析.md`）。
- **每次见面前带着自己的"成果/卡点"来**，别空手说"教教我"——这样每次都能精准教你。

---

## 七、一句话总结
> **别让我替你写，让我教你写。先把事做出来的是你，我负责把它讲成你能独自复现的东西。**
